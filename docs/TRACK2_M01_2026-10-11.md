# M01: AI request audit and human decisions

Local implementation, not pushed/deployed. No migration required: existing V12/V13 `ai_requests` columns are used.

- All existing AI entrypoints run through `AiGateway`: one persisted record per logical request (bounded provider retries belong to that request), including configuration/provider failures. Separate `REQUIRES_NEW` start/complete transactions preserve audit data on caller failure.
- Embedded Gemini reads `usageMetadata`; remote FastAPI/LangChain returns raw usage metadata through nullable `inputTokens`, `outputTokens`, `totalTokens`. Actual model, JSON result/error code, latency and PENDING decision are recorded. Provider exceptions/keys are not persisted. Prompt text is persisted as request data; no service credentials are included.
- `cost_tokens` is provider total count or a sum of known input/output counts. Unknown tokens, monetary cost and currency remain NULL. No pricing or fabricated zero.
- Existing AI response fields remain, with additive `requestId`. `PUT /api/v1/ai/requests/{requestId}/decision` accepts ACCEPTED/IGNORED. Requester or Admin only; failed calls cannot be decided. A same decision is idempotent; changing a terminal decision returns 409. Pessimistic row locking protects concurrent decisions.
- FE analysis panel exposes explicit accept/ignore; these record the decision, not automatic script mutation. The user's AI project-creation flow records ACCEPTED only after project creation succeeds. Decision save failure does not falsely report failed project creation.
